## In Progress

- 2026-08-28: Monetization + current-menu + pick-and-replace (one initiative, since they're linked: the free tier only works if every AI-costing action is metered, and pick-and-replace is exactly such an action). Decided: sign-in is only required to save/favorite a recipe or menu (already worked this way via `showAuthModal` in `ResultsStep`/`MealModal`) — it is *not* required to generate. Instead, everyone (guest or signed-in) shares the same lifetime cap of 7 free generations, tracked via `MenuGenerationHistory` for signed-in users and a cookie counter (`free_gen_count`) for guests; a non-blocking warning appears once 2 or fewer generations remain. Admin account(s) bypass the cap entirely. "Replace this meal" (not yet built) will check the user's own `FavoriteRecipe` library first (free, instant, zero licensing risk since it's the user's own past AI output) before falling back to a metered AI call, with a preview the user must confirm before it overwrites the slot. Done so far: rewrote `checkGenerationRateLimit` in `rate-limit.ts` to a lifetime count (was daily-resetting) with a limit of 7 and an `ADMIN_EMAILS` env-based bypass (kavithasunku@gmail.com, still needs adding to Vercel's env vars too); replaced the dead one-trial-then-sign-in guest cookie in `generate-menu/route.ts` with a real cookie-based counter sharing the same 7-cap and no sign-in gate; added a dismissible "only N free generations left" banner in `planner/page.tsx` once remaining ≤ 2, and removed the now-fully-dead `sign_in_required` generation-error path (sign-in-for-saving is a separate, already-working mechanism). Known limitation: guest counting is cookie-based only, so clearing cookies/incognito resets it — acceptable for now since sign-in isn't required, but means the guest cap isn't airtight. Still open: the "My Menus" list / current-menu (`isCurrent`) concept and where it lives in the nav; the replace-a-meal endpoint and its `MealModal` UI; actual Stripe checkout once there's a concrete paid tier to sell (the quota now exists to gate against, but no billing flow exists yet).
